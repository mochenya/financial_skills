# 股票池维护约定

## 契约与导入

- 变更市场、字段、导入或刷新行为前，核对相关 CLI、数据库和数据源契约与脚本实现。明确证券身份、代码格式、字段来源与映射、可空值、去重和更新行为；不要把不同来源的行业分类视为等同。
- 从表格或其他外部数据导入时，先检查列、代码类型与前导零、市场和重复项，说明映射到哪些字段及未导入的列；不根据名称猜代码。导入后核对逐项结果，报告新增、跳过和失败，保留部分成功的事实。
- 修改脚本行为时同步更新相关契约及 `SKILL.md`；保持主文件中导入字段、市场格式和操作后果清晰，详细边界放在按需阅读的参考文件中。

## 数据源与市场扩展

- 新增或调整数据源、市场或依赖版本时，先研究相关接口及字段契约，并使用代表性真实请求验证身份、证券类型、名称和所需字段；包含相关的代码格式、缺失值和失败情况。区分官方说明、实测与推断，记录版本、日期、样本和局限；空结果或异常不等于证券不存在。
- 将影响使用或维护的来源、字段映射、限制和验证结论写入对应数据源契约；必要时新增参考文档，并从 `SKILL.md` 链接。向用户汇报研究结论、主要取舍和未解决的问题，再按用户授权范围推进；用户仅要求研究时不实施修改。

## 变更与验证

- 优化或更新本 Skill 时使用 `skill-creator`，保留现有用途、授权边界和行为契约；不要因文案精简改变实际规则。
- 数据库结构变更、导入或其他写入遵守用户当前授权边界；迁移前只读核对目标和现有约束，按要求提供具体变更、影响及回退方式。不要在输出或文档中暴露连接凭据。
- 运行 skill 校验及与变更相称的隔离测试；涉及上游时核对固定版本和实测结果，不使用真实股票池做破坏性测试。汇报变更、验证结果、失败项和重要限制。
